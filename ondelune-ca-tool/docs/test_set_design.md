# 测试集设计（50 个用例）

所有客户与对话均为虚构。由 `scripts/make_test_cases.py` 生成，可复现。

## 设计原则

- **以日常为主**：35 个常规用例 + 15 个边界用例，比例接近真实使用（大多数消息是日常维护，少数是难题）。
- **覆盖 6 个场景**：常规用例每个场景 5–6 个；边界用例按风险分布。
- **在维度上变化**：5 类客户画像（藏家、商务送礼、庆祝、新客、沉睡）× 3 个层级 × 3 档熟悉度，另有城市、沟通偏好、对话长短的变化。
- **每个用例都有预期行为**（tags 中的 `expect`）：生成 / 生成+警告 / 不生成，用来检验预检是否正确。
- **边界用例对应具体规则**：每个都对准一条红线或 playbook 规则，用来测量工具的检出率。

## 已知的 v1 局限（运行前即可预见）

- **X06、X15（客户拒绝过 / 决定不买）**：v1 只靠 LLM 裁判判断 R12，预检不会提前警告（v1 实测 X06 未警告）。v2 新增 R12 预检，两者都会警告。X15 的预期在 v2 时从「生成」更正为「生成+警告」。
- **R13（连续未回复）**：触发后三条都被压到 50 字以内，可能导致消息过于单薄（见 D9）。
